# Android verification

The helpers use Python 3.10+, FFmpeg, FFprobe, and Android SDK platform-tools. Set `ANDROID_HOME` for ADB discovery. Set `ANDROID_SERIAL` when several devices are connected. Choose a fresh `CHATSTAMP_QA_RUN_ID` for each run. The default is `fixture`, and generated files go under `dist/android-verification/<run-id>/`. Use `CHATSTAMP_QA_MEDIA_ROOT` to query a run under Pictures, DCIM, or Movies.

Build a standalone debug APK from the repository root.

```powershell
npx expo prebuild --platform android --clean
.\android\gradlew.bat -p android --console=plain --max-workers=2 -I "$PWD\scripts\android-verification\device-test.init.gradle" :app:assembleDebug '-PreactNativeArchitectures=arm64-v8a'
```

Check `android/app/build/outputs/apk/debug/output-metadata.json` for the QA application ID `com.menis10tec.chatstamp.qa` before installing. Use the SDK's ADB for installation and the scripts.

```powershell
$adb = Join-Path $env:ANDROID_HOME 'platform-tools\adb.exe'
& $adb install -r android/app/build/outputs/apk/debug/app-debug.apk
$env:CHATSTAMP_QA_RUN_ID = 'stage-a'
python scripts/android-verification/fixtures.py
$zip = python scripts/android-verification/device.py prepare mixed
& $adb shell am force-stop com.menis10tec.chatstamp.qa
python scripts/android-verification/device.py share $zip
python scripts/android-verification/device.py dump qa-selection
```

Use `prepare` with `text-only`, `no-transcript`, `invalid`, or `large` for the other generated ZIPs. `fixtures.py --skip-large` omits the 128 MiB fixture. A baseline app requires a cold share or the system ZIP picker. Complete or skip onboarding before verifying the selection screen.

Run `media-evidence.py` after saving the mixed fixture to read back the dates for the five baseline media files. Run `large-import.py` while the system picker shows the large ZIP to record sampled memory. Run `cleanup-device.py` after collecting evidence from the synthetic run.

After prebuild, prefetch the current AGP connected runner dependencies without a device.

```powershell
.\android\gradlew.bat -p android --console=plain --max-workers=2 '-Dorg.gradle.internal.http.connectionTimeout=12000' '-Dorg.gradle.internal.http.socketTimeout=12000' -I "$PWD\scripts\android-verification\connected-runner.init.gradle" :chatstamp-native:prepareChatStampConnectedRunner
```

## Stage P storage probe

The standalone Gradle project under the probe directory builds a disposable app and AndroidJUnitRunner test APK. Set a new run ID for each attempt. Use the wrapper generated by Expo prebuild and an installed Android SDK 36 and JDK 17.

```powershell
$env:CHATSTAMP_QA_RUN_ID = 'stage-p-20261116-01'
$probe = @('-p', 'scripts/android-verification/probe', '--console=plain', '--max-workers=2', "-PchatStampProbeRun=$env:CHATSTAMP_QA_RUN_ID")
python scripts/android-verification/fixtures.py --skip-large --probe
.\android\gradlew.bat @probe testDebugUnitTest assembleDebug assembleDebugAndroidTest
python scripts/android-verification/probe.py verify-apks
python scripts/android-verification/probe.py verify-host
```

The standalone probe's connected runner dependencies can be prefetched without a device.

```powershell
.\android\gradlew.bat @probe -I "$PWD\scripts\android-verification\connected-runner.init.gradle" :prepareChatStampConnectedRunner
```

On the unlocked Samsung, use the SDK ADB to confirm the serial and API level. Run the connected identity assertion before any probe write. It checks that the instrumented process has the app UID, targets SDK 36, and uses scoped storage without broad storage permissions. Record the passing test count from Gradle's XML and save the identity log.

```powershell
$adb = Join-Path $env:ANDROID_HOME 'platform-tools\adb.exe'
& $adb devices -l
.\android\gradlew.bat @probe '-Pandroid.testInstrumentationRunnerArguments.class=com.menis10tec.chatstamp.qa.probe.ProbeIdentityTest' connectedDebugAndroidTest
& $adb logcat -d -s 'ChatStampProbe:I' '*:S' | Set-Content -Encoding UTF8 "dist/android-verification/$env:CHATSTAMP_QA_RUN_ID/probe-identity-log.txt"
```

Run the storage assertions on a clean install of the probe pair. The same runner is invoked directly here so the app and its owned rows stay installed for Gallery inspection and cleanup. If both scoped collections reject a document, the picker opens. In the picker, create and select the exact run folder under Documents printed by the command.

```powershell
python scripts/android-verification/probe.py run --allow-saf
python scripts/android-verification/probe.py collect
```

Collect evidence after a failing run as well. The run folder contains both APK manifests, the fixture expectations, the test and permission output, a JSON Lines record of write attempts and observed timestamps, and FFprobe output from the MP4s reopened via their published URIs. The default layout tries shared Pictures, shared DCIM, then split Pictures and Movies on rejection. A fresh diagnostic run can select DCIM or split placement explicitly with `--layout dcim` or `--layout split`.

In Samsung Gallery's creation-date sort, check the run album for newest-first order **purple, yellow, blue, green, red**. Check the red JPEG details for **15 February 2019, 10:30** with the handset on Asia/Jerusalem. Record the Gallery package version, sort setting and timestamps. In a split run, check the combined timeline and both albums separately. Limit screenshots to synthetic media and record the order of the five synthetic items in text if the combined view includes personal photos.

When the probe reports `mtime_required` for PNG or WebP, check that format's separate control album in creation-date sort. The newer file must appear first although the older file was inserted last. The PNG colors are cyan then orange and the WebP colors are white then magenta. Record `mtime-only` for the tested format and destination only after both independent MediaStore results and the Gallery control agree. The scope of the Android and Gallery results is per handset, API, Gallery version, format, and destination.

Close the probe media in Gallery after gathering evidence, then run cleanup with the same fixture run ID. Cleanup deletes rows under the probe app's UID, verifies the run folders are empty and gone, and uninstalls the app and test APK. It can be rerun while the pair is still installed if cleanup reports a failure.

```powershell
python scripts/android-verification/probe.py cleanup
```

Use the result matrix in [the verification log](../../docs/VERIFICATION.md) to record the dates, capabilities, and destination selected for Stage B. The physical Samsung results and cleanup are required for that decision.

## Stage B app save regression

Build and inspect the QA APK using the commands above. Confirm min SDK 30, target SDK 36, and no broad storage permissions. With only the test handset connected, the checked QA binary can also be installed and launched through Expo.

```powershell
npx expo run:android --binary android/app/build/outputs/apk/debug/app-debug.apk --app-id com.menis10tec.chatstamp.qa --no-bundler
$env:CHATSTAMP_QA_RUN_ID = 'stage-b'
python scripts/android-verification/fixtures.py --skip-large --gallery-five
python scripts/android-verification/device.py prepare mixed
```

In Settings, enable Always use message date and keep the default Android media folders. Choose the generated mixed ZIP through the Android picker and save all five media attachments. In Results, check the date outcomes and the Open in Gallery action. Verify the actual file timestamps and indexed values.

```powershell
python scripts/android-verification/media-evidence.py --assert-gallery-five
```

In Samsung Gallery, open the run album and confirm the same order and red JPEG detail time from Stage P. Import the same ZIP again with Skip existing and confirm that all five results say Already saved and the Gallery row IDs remain unchanged. Keep the media evidence file for the run-scoped cleanup command.

```powershell
python scripts/android-verification/cleanup-device.py
```


## macOS/Linux continuation and compact evidence

Use JDK 17 and Android SDK 36. The local signing document records the existing
macOS toolchain paths. Replace the Windows wrapper with `./android/gradlew -p android`
and use an absolute path for `-I`. Keep the two-worker and arm64 settings above.
Before a physical run record `adb shell settings get global stay_on_while_plugged_in`,
run `adb shell svc power stayon usb`, wake with `adb shell input keyevent KEYCODE_WAKEUP`,
and inspect `adb shell dumpsys window policy` for an unlocked keyguard. Do not unlock
a locked phone. Restore the recorded setting when finished.

Set a short run ID and a temporary **working** directory so large fixture archives,
assets, pulled media and full build logs are not included in the curated evidence:

```bash
export CHATSTAMP_QA_RUN_ID=b-20261118
export CHATSTAMP_QA_WORK_ROOT=/tmp/chatstamp-runtime-20261118/stage-b-work
python3 -m unittest discover -s scripts/android-verification -p 'test_*.py' -v
python3 scripts/android-verification/fixtures.py --skip-large --gallery-five
python3 scripts/android-verification/device.py prepare mixed
python3 scripts/android-verification/media-evidence.py --assert-gallery-five --snapshot /absolute/evidence/stage-b-first.json
```

After each duplicate rerun, repeat readback with `--compare /absolute/evidence/stage-b-first.json`
and a new `--snapshot` path. Inventory covers QA-owned rows for the synthetic chat
across roots and sibling folders, so unchanged original IDs cannot hide extra copies.
The additional `undated` fixture contains an unmatched VCF without a filename date,
message date, or raw ZIP date. Select only that document and verify saved/date-unavailable.
Save its exact URI, filename and relative_path in a small JSON list and pass that
file using `cleanup-device.py --evidence /absolute/evidence/undated.json`.

Keep all curated reports/readbacks and essential synthetic screenshots in one output
set below 10,000,000 bytes, cumulatively across the current answer. Exclude build
outputs, ZIP fixtures, pulled media, raw logs and videos from that evidence set.
Only retain evidence newly generated or materially updated during the current run.


## Reproduce the unused-source check

From the repository root, run the exact version and reviewed Expo/native entries:

```sh
npm exec --yes --package=knip@6.46.0 -- knip --config scripts/android-verification/knip.json --include files,exports,types --no-progress
```

This checks source/test callers, not native autolinking reachability. Keep the
native package entry and SDK-matched peer dependencies even when a JS-only
heuristic cannot see their consumer. Do not use bare production mode without
Expo entry discovery or automatically delete intentional production test seams.


## CI bootstrap transport

The optional CI-only `ci-bootstrap.py`/`ci-bootstrap.init.gradle` repair Maven
transport for React Native's unchanged Foojay Gson2.9.1 dependency. The downloader
admits only four SHA256/size-pinned official Central files; it never changes an
app dependency version. `CHATSTAMP_CI_BOOTSTRAP_REPOSITORY` enables the verified
local plugin repository, restricted to three exact GAVs; Plugin Portal remains
available for composite builds. Leave this variable unset for ordinary local
Android builds. The workflow still runs all host/JVM/manifest gates and uses no
signing or Play credentials. Integrity/cache/path/fallback regressions are part
of the105-case Python verification suite.
